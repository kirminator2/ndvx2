# Обновления в работе с данными Яндекс-ЖК

## Проблема

Ранее при обновлении данных Яндекс-ЖК происходило полное удаление старых данных:

1. **Импорт Яндекс-ЖК** - удалял ВСЕ записи из таблицы `yandex_newbuildings`
2. **Обновление связей** - удалял ВСЕ связи из таблицы `PropertyYandexLink`
3. **Потеря данных** - slug'и и другие важные данные терялись при каждом обновлении

## Решение

### 1. Изменена логика импорта Яндекс-ЖК

**Файл:** `backend/app.py`  
**Функция:** `import_yandex_newbuildings()`

**Что изменилось:**
- ❌ Удаление всех старых данных: `YandexNewBuilding.query.delete()`
- ✅ Сохранение существующих записей с обновлением
- ✅ Добавление только новых записей
- ✅ Возврат статистики: количество добавленных и обновленных записей

**Новая логика:**
```python
# Создаем словарь существующих записей для быстрого поиска
existing_buildings = {}
for building in YandexNewBuilding.query.all():
    key = f"{building.complex_id}_{building.building_id}"
    existing_buildings[key] = building

for row in reader:
    key = f"{complex_id}_{building_id}"
    
    if key in existing_buildings:
        # Обновляем существующую запись
        building = existing_buildings[key]
        building.region = row[0]
        building.complex_name = row[1]
        # ... обновление других полей
        updated_count += 1
    else:
        # Создаем новую запись
        yb = YandexNewBuilding(...)
        db.session.add(yb)
        added_count += 1
```

### 2. Изменена логика обновления связей

**Файл:** `backend/app.py`  
**Функция:** `update_yandex_links()`

**Что изменилось:**
- ❌ Удаление всех старых связей: `PropertyYandexLink.query.delete()`
- ✅ Сохранение существующих связей с обновлением
- ✅ Добавление только новых связей
- ✅ Автоматическое создание slug'ов для новых связей

**Новая логика:**
```python
# Получаем существующие связи для проверки
existing_links = {}
for link in PropertyYandexLink.query.all():
    existing_links[link.property_id] = link

for property_id, yandex_building_id, complex_name in links:
    if property_id in existing_links:
        # Обновляем существующую связь
        link = existing_links[property_id]
        link.yandex_building_id = yandex_building_id
        link.yandex_complex_name = complex_name
        updated_links_count += 1
    else:
        # Создаем новую связь
        link = PropertyYandexLink(...)
        db.session.add(link)
        new_links_count += 1

# Создаем slug'и для новых связей
if new_links_count > 0:
    create_slugs_for_yandex_links()
```

### 3. Добавлена функция создания slug'ов

**Файл:** `backend/app.py`  
**Функция:** `create_slugs_for_yandex_links()`

**Что делает:**
- Находит все связи без slug'ов
- Генерирует уникальные slug'и из названий комплексов
- Проверяет уникальность и добавляет счетчики при необходимости

**API endpoint:** `POST /api/create-yandex-link-slugs`

### 4. Обновлена API документация

**Файл:** `backend/templates/api-docs.html`

Добавлен новый endpoint:
- `POST /api/create-yandex-link-slugs` - Создать slug'и для связей Яндекс-ЖК

## Результаты тестирования

### Импорт Яндекс-ЖК
```bash
curl -X POST http://localhost:5000/api/import-yandex-newbuildings
```

**Результат:**
```json
{
  "success": true,
  "added_count": 450,      // Новые записи
  "updated_count": 71321,  // Обновленные записи
  "message": "Импорт Яндекс-ЖК завершен"
}
```

### Обновление связей
```bash
curl -X POST http://localhost:5000/api/update-yandex-links
```

**Результат:**
```json
{
  "success": true,
  "new_links_created": 0,        // Новые связи
  "existing_links_updated": 3090 // Обновленные связи
}
```

### Создание slug'ов
```bash
curl -X POST http://localhost:5000/api/create-yandex-link-slugs
```

**Результат:**
```json
{
  "success": true,
  "created_count": 2251,
  "message": "Создано 2251 slug'ов для связей Яндекс-ЖК"
}
```

## Преимущества

1. **Сохранение данных** - никакие данные больше не теряются
2. **Сохранение связей** - все связи между объектами и ЖК сохраняются
3. **Сохранение slug'ов** - красивые URL остаются рабочими
4. **Статистика** - видно, сколько записей добавлено/обновлено
5. **Автоматизация** - slug'и создаются автоматически для новых связей

## Обратная совместимость

Все существующие API endpoints продолжают работать как прежде. Изменения касаются только внутренней логики обработки данных.
