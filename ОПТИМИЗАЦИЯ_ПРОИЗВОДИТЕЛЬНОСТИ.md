# Оптимизация производительности фронтенда

## Проблема
Первая загрузка фронтенда была медленной из-за большого объема данных, загружаемых с сервера.

## Решения

### 1. Легковесные API endpoints

Созданы новые оптимизированные API endpoints:

- `/api/properties-light` - быстрая загрузка списка объектов недвижимости
- `/api/complexes-light` - быстрая загрузка списка ЖК  
- `/api/stats-light` - легковесная статистика

**Преимущества:**
- Загружают только необходимые поля
- Уменьшен размер страницы (20 вместо 50)
- Оптимизированные SQL запросы
- Меньший объем передаваемых данных

### 2. Кэширование на фронтенде

Добавлено кэширование с помощью React Query:

```typescript
// Кэширование для быстрой загрузки
staleTime: 5 * 60 * 1000, // 5 минут
gcTime: 10 * 60 * 1000, // 10 минут
```

**Преимущества:**
- Данные кэшируются на 5-30 минут
- Быстрая загрузка при повторных запросах
- Снижение нагрузки на сервер

### 3. Индексы базы данных

Добавлены индексы для ускорения запросов:

```sql
CREATE INDEX IF NOT EXISTS idx_property_price ON property(price)
CREATE INDEX IF NOT EXISTS idx_property_total_area ON property(total_area)
CREATE INDEX IF NOT EXISTS idx_property_rooms_count ON property(rooms_count)
CREATE INDEX IF NOT EXISTS idx_property_address ON property(address)
CREATE INDEX IF NOT EXISTS idx_property_id_desc ON property(id DESC)
```

### 4. Пагинация и ленивая загрузка

- Реализована бесконечная прокрутка
- Загрузка данных по мере необходимости
- Индикаторы загрузки для лучшего UX

## Результаты оптимизации

## Мониторинг

Для мониторинга производительности добавьте логирование:

```python
import time

@app.before_request
def before_request():
    g.start = time.time()

@app.after_request
def after_request(response):
    diff = time.time() - g.start
    print(f"Request to {request.endpoint} took {diff:.3f} seconds")
    return response
```
